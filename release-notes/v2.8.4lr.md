**[App Page](https://sevmorris.github.io/DoublEnder/)**

Nothing changes in how DoublEnder records. This release makes updating safer. Most of it takes effect from the update after this one, because the version you have now installs this one.

**New**
- **If a new version won't start, DoublEnder goes back to the one you had.** Before an update replaces anything, DoublEnder checks that the new version starts on your Mac. After installing, it keeps the previous version until the new one has been open for a few seconds. If the new version fails to open three times in a row, DoublEnder puts the previous version back and reopens it, and doesn't offer that version again at launch. **Check for Updates…** still offers it if you ask.

**Changed**
- **An update waits for your recording before it downloads, not just before it installs.** Downloading and unpacking a new version no longer runs alongside a take. If you start recording during a download, the download stops and starts again once you've finished.
- **Nothing from the updater appears over a recording.** If an update fails while you're recording, DoublEnder tells you after you stop. An update that had to wait asks before it relaunches, and never relaunches while any DoublEnder dialog is open.
- **An update won't fill your disk.** It doesn't start unless there's room for the new version and enough left over to start a recording. A download that stops making progress for 30 seconds is given up.
- **Quitting during an update leaves nothing behind.** DoublEnder stops the download and cleans up before it quits. Anything an interrupted update left, after a force quit or a crash, is removed the next time DoublEnder opens.
- **A copy that can't update itself where it is says so up front.** On a drive that can't swap an app in one step, such as an exFAT or network drive, the prompt explains and offers **Download**. It used to download everything first and then fail.

**Fixed**
- **Cancel stops an update at once.** While DoublEnder was checking a download, Cancel waited for the check to finish.
- **One update at a time.** Choosing **Check for Updates…** while the check at launch was still answering could show two prompts and start two downloads. It now brings up the update already under way.
- **The USB audio prompt no longer opens on top of another dialog.** The new device is in the input picker either way.

**Developer**
- One `UpdateCoordinator` runs every update. `AppActivity` is the single definition of what the app is in the middle of, and both the quit intercept and the updater read it, so an update's own quit never meets the "Recording in progress" question. Every dialog opens through `ModalGate`.
- The install is one synchronous step (`UpdateCommit`), with no suspension from its last check to the quit. It re-checks the staged copy, confirms the app at its path is still the running one, and starts the relaunch helper before the swap. Probation and rollback are in `UpdateRollback`. See "SelfUpdater — installing an update" in the Theory of Operation.
- A modal started inside a main actor task stops the main dispatch queue until it closes. The updater's dialogs now open from the run loop instead.
- `SelfUpdater.swift`, shared with the sibling apps, runs hdiutil and ditto with a deadline and real cancellation, and limits downloads by stall time, size and free space. All ten copies were updated together.
- Running the tests no longer asks for microphone access.
