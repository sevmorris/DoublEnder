**[App Page](https://sevmorris.github.io/DoublEnder/)**

DoublEnder leaves your Mac's settings and your other recordings alone. It no longer changes the Mac's microphone for other apps, and a second copy of DoublEnder no longer interferes with the first.

**Fixed**
- **DoublEnder no longer changes your Mac's microphone for other apps.** Every launch used to make the built-in microphone the Mac's input, and so did every microphone you picked. If you were already in a call on a USB microphone, and the call app follows the Mac's input, the call dropped to the laptop microphone. DoublEnder still records from the microphone you pick; it just doesn't change the Mac's choice for anything else.
- **Opening a second copy no longer deletes a take the first one is recording.** DoublEnder and DoublEnder Cloud share the Desktop, and a second copy of either can be opened while the first is recording, from its disk image for example. At launch it took the take being recorded for one left by a crash and deleted it. It now leaves alone any take that is still being written.
- **Opening a second copy no longer deletes the first one's update.** A copy opened from the disk image while the installed one was downloading an update, or holding one ready, deleted it.
- The last two need both copies to be 2.8.6lr or later: an earlier version neither marks what it is using nor checks for it.

**Developer**
- A process holds an flock on what it is using: a take's `.pcmrec` sidecar, created locked while it records (`PCMSidecar`), and an update's staging folder from the moment it goes on the staging journal (`InUseLock`). Crash recovery and the launch sweep pass over anything locked. The kernel drops the lock when the process ends, however it ends, so what a crash leaves is still recovered or swept at the next launch. See the Theory of Operation.
- `setDevice` no longer sets the system default input. It remembers the pick instead, and `start()` (TRY AGAIN) rebuilds the session on it while it is connected (`AudioEngine.restartInputUID`); it used to take the system default, which was the pick only because `setDevice` had moved it.
- `release.sh` sets `POSIX_TRAPS` before its EXIT trap, so a step that fails inside a function still runs the cleanup.
