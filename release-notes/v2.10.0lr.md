**[App Page](https://sevmorris.github.io/DoublEnder/)**

A diagnostics console for troubleshooting a take, a safer way back from a bad update, and a take that fails to save no longer freezes the app.

**New**
- **A Service Monitor for troubleshooting.** Open **About DoublEnder** from the DoublEnder menu, then Option-click the icon (or click it three times). A small console opens that shows what the recorder is doing: which microphone it is using, at what sample rate and buffer size, each step of a take, and every few seconds the level and the disk space. Type `help` for its commands; `dump` copies everything to the clipboard to send to whoever is helping you. Nothing in it is saved or sent anywhere by itself, and it is gone when you quit.

**Fixed**
- **Stopping a long take whose file failed to save no longer freezes DoublEnder.** When the recording can't be finished (a full disk is the usual reason), DoublEnder rebuilds it from its backup copy. It used to do that in a way that froze the app for as long as it took, which on a long take was a long time. It now works in the background.
- **A full disk no longer leaves a broken "(recovered)" file.** If there isn't room to rebuild the take, DoublEnder now deletes the part-written copy rather than leaving a file that claims to be the whole take, and keeps the backup so the next launch can try again.
- **The way back from a bad update is kept somewhere safe.** If a new version fails its first launches, DoublEnder puts the previous one back. It kept that previous version in the Mac's temporary folder, which macOS can clear after a few days, so a version you didn't open for a week could have nothing to go back to. It is now kept in DoublEnder's own folder. And an update no longer installs when the disk is too full to record how to undo it.
- **Every USB input is offered at launch, not just the newest.** With a webcam and a USB microphone both plugged in, choosing **Keep Current** for the webcam meant the microphone was never offered. DoublEnder now offers the next one. On a Mac with no built-in microphone, the input it starts on is skipped rather than ending the offers.

**DoublEnder Cloud**
- An upload that fails because the Mac has just woken, or the Wi-Fi has dropped, now waits up to two minutes for the connection to come back before it spends a retry, so it no longer gives up before the Wi-Fi rejoins.
- Quitting while DoublEnder checks for updates in the background no longer throws away an update it had already downloaded.
- A take that was waiting to upload and has since been moved or deleted is now reported at launch, so you know to send it another way. It used to be dropped without a word.
- When a microphone is unplugged during a take, "Uploaded" now waits for "Microphone disconnected" to be closed rather than opening on top of it.

**Developer**
- `DiagnosticLogger` keeps the Service Monitor's lines in a 500-line ring in memory, with the input handshake, low-quality warning, writer-open and take-start lines pinned outside it so a long take can't scroll them out. `log` never waits on the main thread, so the writer queue can't be stalled by the UI. See "The Service Monitor" in the Theory of Operation.
- Recovery at STOP converts the `.pcmrec` sidecar off the main thread (`PCMSidecar.recoverFailedTake`) while `AudioEngine` keeps the sidecar open and locked, so a second copy can't recover it at the same time.
- After an update's swap, the previous version moves to `Previous Version.noindex` beside the update state in Application Support, and the probation record follows it (`UpdateRollback.keepPrevious`). A probation record that can't be saved refuses the swap (`UpdateCommit.Refusal.cannotKeepPrevious`).
- Upload retries wait for `CloudConnectivity.isReady`, for up to 120 s, on a connectivity error (`UploadRetry`). `ModalGate.afterDialogs` runs a dialog once no other is up. `installAtQuit` installs a waiting copy in any phase but `.committing` and `.relaunching`.
