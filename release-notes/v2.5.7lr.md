**[App Page](https://sevmorris.github.io/DoublEnder/)**

**Fixed**
- **Crash recovery no longer offers to keep a recording that won't play.** After a crash, the recovery dialog judged whether the interrupted file was a finished recording by its size, and almost every crashed recording is large enough to pass. So it offered Keep Saved for a file that would not open, and keeping it discarded the recovery copy, the only way back to that audio. It now checks that the file actually plays.
- **The level meter shows the level you're recording.** With a two-channel interface, the file came out 3 dB louder than the meter showed, so a voice sent to both inputs could clip the recording while the meter still showed headroom. The meter, and the crash-recovery copy, now mix the channels the way the recording does.
- **A brief interruption no longer ends the take early, and a silent restart is caught.** When another app took the microphone, DoublEnder gave up after 3 seconds rather than the intended 5. And if the input came back but sent no sound, nothing noticed. Both are fixed.
- **No more "your audio is safe" when nothing was captured.** If a recording failed before any sound arrived, DoublEnder said the audio was safe and would be recovered on relaunch, though there was nothing to recover. It now says no audio was captured.
- **A take stopped for lack of disk space says so.** When the Desktop's disk ran low mid-recording, the take was saved with the usual confirmation and no reason given. The confirmation now says the recording stopped early, and why.
- **The Desktop permission prompt explains itself.** macOS asks before DoublEnder reads your Desktop, where it saves recordings and looks for any left by a crash, and the prompt now says why. Help names both launch prompts and where to turn each back on, and no longer says the RECORDING light flashes: it has been solid since 2.2.0.
